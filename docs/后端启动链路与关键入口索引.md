# 后端启动链路与关键入口索引（Flowise-plus）

这份文档的目的：让你能“顺藤摸瓜”读代码——从启动命令一路跟到核心模块初始化与路由注册位置。

## 1. 启动从哪里开始？

你在根目录执行的命令（开发/生产）最终都会落到 `packages/server`：

- `pnpm dev`：turbo 并行启动各包的 dev 脚本（server 用 `nodemon`）
- `pnpm start`：在根目录脚本里 `cd packages/server/bin && run start`

在 `packages/server/package.json` 里可以看到：

- `scripts.start:*` → `bin/run`（oclif 命令）
- `scripts.dev` → `nodemon`

## 2. 我们在复刻升级版新增的“配置单入口”

为了避免多个地方各自 `dotenv.config(...)` 导致行为不一致，`Flowise-plus` 新增：

- `packages/server/src/config/loadEnv.ts`
  - `loadEnvOnce()`：只加载一次 `packages/server/.env`（保持上游 override 行为）
- `packages/server/src/config/env.ts`
  - `getServerEnv()`：用 `zod` 解析 + 默认值 + 类型校验（例如 `PORT`、`DEBUG`、`LOG_LEVEL`）
- `packages/server/src/config/index.ts`

当前已收敛的点：

- `packages/server/src/commands/base.ts`：不再单独调用 `dotenv.config`，改为 `loadEnvOnce()`
- `packages/server/src/utils/config.ts`：不再单独调用 `dotenv.config`，改为 `loadEnvOnce()` + `getServerEnv()`
- `packages/server/src/index.ts`：`start()` 一开始先 `getServerEnv()`，让配置错误尽早暴露

## 3. 后端服务真正的入口文件

`packages/server/src/index.ts`

重点关注这三段：

- `start()`：创建 http server，确定 `host/port`，然后执行初始化流程并监听端口
- `initDatabase()`：数据源初始化、迁移、Identity/NodesPool、加密 key、鉴权 secret、限流、缓存、telemetry、SSE、队列等
- `config()`：中间件、鉴权判断、metrics、路由挂载、静态 UI、错误处理中间件

## 4. API 路由入口在哪里？

- `packages/server/src/routes/index.ts`（API v1 的路由聚合）
- 在 `packages/server/src/index.ts` 中挂载：`this.app.use('/api/v1', flowiseApiV1Router)`

（你后续做 RBAC/多租户时，通常会在 routes 的聚合层或认证中间件层切入）

## 5. 你学习时的“建议阅读顺序”

建议按以下顺序读（每一步都能回答一个“系统是怎么跑起来的”问题）：

1) `packages/server/bin/run`（命令入口，了解 start/worker/user 等命令是怎么触发的）
2) `packages/server/src/commands/*`（命令层如何把 flags 写入 env）
3) `packages/server/src/index.ts`（服务初始化与路由挂载主干）
4) `packages/server/src/DataSource.ts` + `src/utils/typeormDataSource.ts`（数据库连接与迁移）
5) `packages/server/src/routes/**` + `src/controllers/**` + `src/services/**`（业务层分层）
6) `packages/server/src/utils/logger.ts`（日志与脱敏策略）
