# 客服机器人（多渠道）落地方案（Flowise-plus）

目标：用最小成本把“官网在线客服”跑通，并在同一套后端上逐步接入企微/钉钉/公众号，最终形成可运营的客服系统。

## 1. 你现在已经拥有的能力（Flowise 原生）

- **网页嵌入小组件**：UI 里可以生成 `flowise-embed` 的代码（Popup / Full Page）。
- **公开 Chatbot 链接**：形如 `/chatbot/{chatflowid}` 的页面。
- **公共配置接口**：`/api/v1/public-chatbotConfig`（用于 embed 获取配置）
- **对外问答入口**：`/api/v1/prediction/:id`（外部请求走这里，支持 streaming）
- **会话与记忆**：`chatId/sessionId` + memory 节点（会话历史持久化到 DB）

## 2. Flowise-plus 增强（已落地的两项）

### 2.1 合规/敏感词拦截（MVP）

已在 `packages/server` 加了一个最小合规守卫：在问答入口处检查 `req.body.question`，命中敏感词则直接返回。

- 配置项（写在 `packages/server/.env`）：
  - `CS_FORBIDDEN_TERMS=`：逗号分隔，例如 `博彩,借贷,色情`
  - `CS_BLOCK_RESPONSE=`：命中后的提示语

### 2.2 转人工/留资（MVP）

新增接口：

- `POST /api/v1/support/handoff`

请求体（示例）：

```json
{
  "chatflowid": "xxxx",
  "chatId": "optional-chat-id",
  "name": "张三",
  "email": "a@b.com",
  "phone": "13800000000",
  "issue": "我想转人工咨询套餐价格",
  "channel": "web"
}
```

返回体（示例）：

```json
{
  "ok": true,
  "leadId": "xxxx",
  "chatId": "yyyy",
  "message": "已提交人工协助请求，我们会尽快联系你。"
}
```

说明：

- 当前版本复用 `Lead` 表快速闭环（便于你先上线）。
- 同时已新增 `SupportTicket`（工单）作为“主”数据：支持状态/优先级/渠道/指派/标签/metadata（跨数据库迁移已补齐）。

工单 API：

- `POST /api/v1/support/tickets`
- `GET /api/v1/support/tickets?chatflowid=...&status=...&channel=...`
- `PATCH /api/v1/support/tickets/:id`

`/api/v1/support/handoff` 现在会 **同时创建 ticket（主）+ lead（兼容）**，返回 `ticketId`。

## 3. 官网落地（最小闭环）

1) 在 Flowise UI 创建一个 Chatflow（知识库/RAG 或 FAQ）
2) 在“Share / Embed”里拿到 `flowise-embed` 代码，嵌入官网
3) 在你的前端增加一个“转人工”按钮（或让机器人在某些条件下提示转人工）
4) 点击转人工时调用 `/api/v1/support/handoff`，让客服团队收到线索（你可先用日志/邮件/企业微信 webhook 通知）

## 4. 多渠道接入（建议路线）

建议你按“统一入口 → 适配器”的方式做：

- **统一入口**：把所有渠道消息归一成 `{ channel, externalUserId, text, attachments, metadata }`
- **统一响应**：把 Flowise 返回归一成 `{ text, citations, actions, handoff }`
- **适配器层**：
  - 企微：接收消息/验签 → 转成统一入口 → 调 `prediction` → 回消息
  - 钉钉：同上
  - 公众号：同上

已提供一个“统一 webhook”骨架（先跑通链路）：

- `POST /api/v1/support/channels/:channel/webhook`

请求体：

```json
{
  "chatflowid": "xxxx",
  "text": "用户发来的内容",
  "externalUserId": "渠道侧用户ID",
  "metadata": { "any": "thing" }
}
```

它会把 `chatId` 归一成 `"{channel}:{externalUserId}"` 并调用内部执行（绕过 API Key 校验，便于你做渠道网关）。

### 4.1 飞书接入（MVP，已提供服务端回调）

新增回调地址：

- `POST /api/v1/support/feishu/webhook`

你需要在 `packages/server/.env` 配置：

- `FEISHU_APP_ID`
- `FEISHU_APP_SECRET`
- `FEISHU_VERIFICATION_TOKEN`（用于校验回调来源）
- `FEISHU_ENCRYPT_KEY`（可选，开启后会做签名校验）
- `FEISHU_DEFAULT_CHATFLOW_ID`（飞书默认对应的 chatflowid）

飞书开放平台配置（事件订阅）：

- 回调地址填上你的公网地址 + `/api/v1/support/feishu/webhook`
- 首次保存会触发 `url_verification`，服务端会原样返回 `challenge`
- 订阅消息事件（例如 `im.message.receive_v1`）

## 5. 下一阶段我建议你做的“真升级”（最值）

- **SupportTicket 实体 + 状态机**：new/open/pending/closed，支持指派、标签、优先级
- **人工兜底联动**：在聊天中插入“人工接入中”的系统消息；把会话摘要+最近 N 条对话同步给客服
- **工单分流**：用节点做分类（售前/售后/技术/投诉），不同队列不同 SLA
- **审计与报表**：命中合规次数、转人工率、解决率、响应时长、热门问题
